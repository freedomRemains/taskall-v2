## 概要

本資料では、AIが開発作業を行う際に守るべきルールを規定します。

- 新しい項目を追加する場合は、マークダウンにハイフン3文字で区切り線を入れ、シャープ3文字の小見出しをつけてください。
- ルール記述は原則として箇条書きでお願いします。
- 別途、見やすさを考慮して図表を付与してもよいものとします。

### 基準ディレクトリについて

- AIが開発作業を行う際の基準ディレクトリは `/home/develop/taskall-v2` であり、当該ディレクトリを環境変数として `/home/develop/env/taskall_v2_env.sh` にて登録する。(sourceコマンドにて取り込む)
- 上記シェルの配置先ディレクトリは `/home/develop/env` とする。理由は次の通り。
    - AIの作業環境は、CLIツール(`/snap/copilot-cli/...`配下)から `bash --norc --noprofile` で都度新規プロセスとして起動されるサンドボックスであり、`~/.bashrc` や `~/.profile` を編集しても自動読込されず、次回コマンド実行時には反映が失われる（`export`した環境変数はコマンド呼び出しごとに揮発する）。
    - このため、`~/.bashrc` に環境変数を追記する方式は使えず、各コマンド実行時に明示的に `source` することが必須となる。
    - `/home/develop` 配下であればAIも書き込み・参照が可能であり、`taskall-v2` リポジトリ内に置くとリポジトリ管理対象になってしまうため、リポジトリ外の `/home/develop/env` を採用した。
- 実際の登録内容・使い方は次の通り。

```sh
# /home/develop/env/taskall_v2_env.sh の内容
export TASKALL_V2_HOME=/home/develop/taskall-v2
export JAVA_HOME=/home/develop/jdk21
export PATH="$JAVA_HOME/bin:$PATH"
export TASKALL_V2_APP_PORT=8090
```

- 使い方: 各コマンド実行時、コマンドの先頭で明示的に読み込む。

```sh
source /home/develop/env/taskall_v2_env.sh && cd $TASKALL_V2_HOME && ./gradlew test
```

### 開発作業時のユーザについて

- AIが開発作業を行う際のOS上のユーザは `develop` である（`whoami`コマンドの実行結果より確認）。

---

### WSLユーザについて

- AIの開発作業環境はWSL2上のLinux（Ubuntu Core、カーネル `6.18.33.2-microsoft-standard-WSL2`）であり、WSL上のユーザは `develop` である（`uname -a`・`/proc/version`より確認）。

---

### JDKについて

- AIが開発作業を行うJavaの位置は `/home/develop/jdk21/bin/java`（OpenJDK 21、Temurin-21.0.11+10）であり、環境変数として `/home/develop/env/taskall_v2_env.sh` にて登録する。(sourceコマンドにて取り込む)
- AIの作業環境には `/usr/bin/java` は存在しない（サンドボックス環境のため、ユーザが普段VSCodeで使用している `/usr/bin/java` とは別環境）。そのためAIは `/home/develop/jdk21/bin/java` を使用する。

---

### アプリ起動ポート番号について

- AIが開発作業を行う際に使うアプリ起動ポートは `8090` とする。環境変数 `TASKALL_V2_APP_PORT` として `/home/develop/env/taskall_v2_env.sh` に登録済みであり、`./gradlew bootRun --args='--server.port=8090'` のように使用する。

---

### アクセス許可の履歴について

- AIが開発作業を行う際にアクセス許可を求める場合は `~/request_history.md` に申請内容を追記する。
- 追記形式は「日時・コマンド内容・許可/拒否結果」を1行程度で簡潔に記載する。

- AIが開発作業を行う際は、次のコマンドでブランチ作成する。


### プルリク作成コマンドについて

- AIが開発作業を行う際は、次のコマンドでプルリクを作成する。
- AIの作業環境には `gh` CLIおよびプルリク作成用のMCPツールが存在しないため、GitHub REST APIをPythonの`urllib`から直接呼び出して作成する。認証トークンは `~/.git-credentials` に保存されているものを利用する。

```sh
source /home/develop/env/taskall_v2_env.sh
cd $TASKALL_V2_HOME
git push -u origin feature/<issue番号>
python3 - << 'EOF'
import json, re, urllib.request
with open('/home/develop/.git-credentials') as f:
    line = f.read().strip()
m = re.search(r'https://([^:]+):([^@]+)@github.com', line)
token = m.group(2)
data = json.dumps({
    "title": "<PRタイトル>",
    "head": "feature/<issue番号>",
    "base": "develop",
    "body": "<PR本文>"
}).encode()
req = urllib.request.Request(
    "https://api.github.com/repos/freedomRemains/taskall-v2/pulls",
    data=data,
    headers={"Authorization": f"token {token}", "Accept": "application/vnd.github+json", "Content-Type": "application/json"},
    method="POST"
)
with urllib.request.urlopen(req) as resp:
    print(json.load(resp)["html_url"])
EOF
```

- ブランチ作成・プルリク作成いずれも、これまでの作業では上記手順で問題なく成功している。今後、失敗事例が派生した場合は、コマンド実行時のエラーメッセージ・終了コードを本ファイルまたは `~/request_history.md` に記録し、傾向分析ができるようにする。

### issue対応時(プルリク作成時)に実施するタスク

本ツールはDBモデル構造を生かしたローコードツールであり、「src/main/resources/db」配下のDB資材に基づいて動作します。  
GitHubから資材をクローンしたユーザがすぐに本ツールを動かせるよう、「src/main/resources/db」配下のDB資材はクリーンな状態を保つ必要があります。

- 「taskallv2.db」を削除して、Gradle全テストを実施してください。
    - 「TaskallV2ApplicationTests」といった「@SpringBootTest」を伴うテストクラスを実行すると、「DbInitializer」が「ApplicationRunner」経由で起動します。
    - DbInitializer は起動時に TBL_DEF テーブルの存在を確認し、存在しない場合のみ DbInitializationService.initializeDatabase() を呼び出してDROP→CREATE→INSERTを実行します。既に存在すればスキップします（実機で両パターンとも確認済み）。
    - なおこのとき、「src/main/resources/db/data」から生成された「src/main/resources/db/sql」配下のSQLが実行対象となります。
    - 「taskallv2.db」を削除してGradle全テストを実施することにより、「src/main/resources/db」配下のDB資材に基づいた最新状態でDBがクリーンアップされます。
    - この状態で動作検証を行いたいため、本ルールを策定しました。
