二段階認証の実装

現状のログインの仕組みに二段階認証の仕組みを追加する。

### 二段階認証の処理概略

- メールアドレス及びパスワードによる認証は、次の通り変更する。
    - 認証成功でもまだログインとは扱わない。制御用テーブルに「first_auth_pass(一次認証通過)」というステータスを登録するにとどめる。
    - ユーザが誤ったメールアドレス、パスワードを入力した場合は、エラー表示する点は現状と変わらない。
- メールアドレス及びパスワードによる認証が成功したら、メールアドレス宛に6桁のランダムな数字のメールを送信する。
    - メールタイトルは「二段階認証パスコード」、本文は「次の6桁の数字をご入力ください。(改行)  XXX XXX」とする。  
      (改行後に半角スペース2文字を入れ、3文字、半角スペース、3文字で、6桁の数字を記述する)
    - 画面は6桁の数字の入力モードとなって待機する。
    - メールの有効期限は5分とする。
    - ユーザが正しく数字を入力した場合はログイン成功と見なし、ログイン後の画面(マイページ)に遷移する。
    - ユーザが誤った数字を入力した場合は、エラーメッセージを画面に表示して再入力を待機する。
    - ユーザが5回誤った数字を入力した場合は、アカウントを15分間ロック状態とする。

### 制御用のテーブル追加

- 二段階認証を制御するため、「ログイン状況(LOGIN_STATUS)」テーブルを新設する。

| テーブル物理名       | テーブル論理名       |
| -------------------- | -------------------- |
| LOGIN_STATUS         | ログイン状況         |

| フィールド物理名     | 型                   | フィールド論理名     |
| -------------------- | -------------------- | -------------------- |
| LOGIN_STATUS_ID      | INT                  | ログイン状況ID       |
| ACCNT_ID             | INT                  | アカウントID         |
| SESSION_ID           | VARCHAR(256)         | セッションID         |
| CURRENT_STATUS       | VARCHAR(256)         | 現在ステータス       |
| FAIL_CNT             | INT                  | 認証失敗回数         |
| EXPIRES_AT           | TIMESTAMP            | 有効期限             |
| (VERSION以下は略)    |                      |                      |

    - 「現在ステータス」には、次のいずれかの値が入るものとする。
        - 「not_auth(未認証)」
        - 「first_auth_pass(一次認証通過)」
        - 「first_auth_fail(一次認証失敗)」
        - 「second_auth_fail(二次認証失敗)」
        - 「accont_lock(アカウントロック)」
        - 「auth_success(認証成功)」

- 「TBL_DEF.txt」に「ログイン状況(LOGIN_STATUS)」テーブルの定義を追加する。
    - 「TBL_DEF_ID」は「1002201」始まりの連番とする。
    - カラム定義は上記の通りとする。

### 二段階認証処理

- 「ログイン状況(LOGIN_STATUS)」テーブルのレコードは、メールアドレス・パスワードによる一次認証を最初に実行したとき(POST時)に作成する。
- ただしメールアドレスがアカウントテーブルにない場合は、レコード作成は行わない。
- 「ログイン状況(LOGIN_STATUS)」テーブルに、メールアドレスが指すアカウントIDのレコードが既に存在する場合は、次の処理を実行する。
    - 「ログイン状況(LOGIN_STATUS)」テーブルのレコードは物理削除し、作成しなおす。(流用は禁止とする)
- 「現在ステータス」は「not_auth(未認証)」とし、「有効期限」は30分、「認証失敗回数」は0とする。  
  なおより正確には「有効期限」は30分後を示すタイムスタンプ値となる。以降の記述でも同様とする。
- メールアドレス・パスワードによる一次認証が成功した場合、「現在ステータス」は「first_auth_pass(一次認証通過)」、「有効期限」は5分、「認証失敗回数」は0とし、メールアドレス宛に二段階認証メールを送信する。
- メールアドレス・パスワードによる一次認証が失敗した場合、「現在ステータス」は「first_auth_fail(一次認証失敗)」とし、「認証失敗回数」を1増やす。
    - 「認証失敗回数」が5回になった場合は、「現在ステータス」は「accont_lock(アカウントロック)」、「有効期限」は15分とする。
- メールによる二段階認証が成功した場合は、次の処理を実行する。
    - 「ログイン状況(LOGIN_STATUS)」テーブルの「ログイン状況」を「auth_success(認証成功)」とする。
- メールによる二段階認証が失敗した場合、「現在ステータス」は「second_auth_fail(二次認証失敗)」とし、「認証失敗回数」を1増やす。
    - 「認証失敗回数」が5回になった場合は、「現在ステータス」は「accont_lock(アカウントロック)」、「有効期限」は15分とする。
    - 未ログインのTOP画面に遷移させ、「アカウントは現在、ロックされています。(改行)しばらくしてから再度アクセスしてください。」というエラーを画面に表示する。

### ロック解除処理について

上記二段階認証処理で、「現在ステータス」が「accont_lock(アカウントロック)」状態になることがある。
ロック解除については、次の通り処理する。

- メールアドレス・パスワード認証のPOST処理の冒頭部で、制御処理を実行する。
    - 「ログイン状況(LOGIN_STATUS)」テーブルをアカウントID、「現在ステータス」が「accont_lock(アカウントロック)」という条件で検索する。
        - 現在時刻が「有効期限」を過ぎている場合は、次の処理を実行する。
            - 「ログイン状況(LOGIN_STATUS)」テーブルのレコードを物理削除する。
        - 現在時刻がまだ「有効期限」に到達していない場合、「アカウントは現在、ロックされています。(改行)しばらくしてから再度アクセスしてください。」というエラーを画面に表示する。
- 二段階認証(6桁の数字入力)のPOST処理冒頭部で、次の個別制御処理を別途実行する。
    - 「ログイン状況(LOGIN_STATUS)」テーブルをアカウントID、「現在ステータス」が「first_auth_pass(一次認証通過)」もしくは「second_auth_fail(二次認証失敗)」、現在時刻が「有効期限を過ぎている」という条件で検索する。  
      該当レコードがある場合、次の処理を実行する。
        - 未ログインのTOP画面に遷移させ、「有効期限切れです。再度、メールアドレス及びパスワードによる認証をお願いします。」というエラーを画面に表示する。

### 特殊ケースの想定

- メールアドレス・パスワードのログイン画面のままセッションタイムアウト時間(30分)を経過する。そしてログイン(POST)を実行。
    - まだ「ログイン状況(LOGIN_STATUS)」テーブルにレコードが作られないタイミング。
        - 初回ログインの場合は何の問題もなし。
    - 既にログインしているが、ログイン前に起動していた別タブでセッションタイムアウト後に認証情報を入れてログイン。
        - この場合も「ログイン状況(LOGIN_STATUS)」テーブルにレコードがないので問題なし。(事前処理で物理削除されているはず)
    - 未ログインだが5回未満のログイン失敗がある。
        - セッションタイムアウト、これは有効期限切れの「ログイン状況(LOGIN_STATUS)」テーブルレコード削除で処理されるので、問題なし。
    - 未ログインかつロック状態である。
        - この場合、セッションタイムアウト(30分)より前にロック解除される。  
          有効期限切れの「ログイン状況(LOGIN_STATUS)」テーブルレコード削除で処理されており、問題なし。
- 一次認証を通過したまま、5分が経過する。(有効期限切れ)
    - 6桁の番号を入力。
        - この場合は、二段階認証の冒頭部処理が動きエラー処理となる。問題なし。
    - 事前に起動していた別タブでメールアドレス・パスワードを入力。
        - この場合も同様で、「ログイン状況(LOGIN_STATUS)」テーブルのレコードは物理削除し、作成しなおしとなるはずなので、問題なし。
- 一次認証を通過したまま、セッションタイムアウト時間(30分)を経過する。
    - 6桁の番号を入力。
        - この場合は、二段階認証の冒頭部処理が動きエラー処理となる。問題なし。
    - 事前に起動していた別タブでメールアドレス・パスワードを入力。
        - この場合も同様で、「ログイン状況(LOGIN_STATUS)」テーブルのレコードは物理削除し、作成しなおしとなるはずなので、問題なし。
